# Brief P4 — CVE research, vulnerable builds, PoCs

**Worktree:** `../Portcullis-worktrees/p4-cve-infra` on branch `p4-cve-infra`.
**Read first:** spec §8.2 and §11, Tasks 4.1–4.3 in the plan. This unit writes **no library code** and runs alongside P1.

**Goal.** Choose the six CVEs, pin and build the vulnerable parsers under ASan, and commit the triggering inputs with provenance — the ground truth the Wave 2 contracts and Wave 3 harnesses stand on.

**Task 4.1 — select six CVEs** (`cve/SELECTION.md`). Criteria: a bounds violation driven by a length or count field; a public PoC whose provenance can be stated; the vulnerable version builds under ASan on Linux. Two per family. Candidates to verify first — TLS: CVE-2014-0160 (OpenSSL 1.0.1f heartbeat), CVE-2014-0195 (DTLS fragment length); PNG: CVE-2015-8126, CVE-2015-8540; TIFF: CVE-2017-9147, CVE-2016-9535. Replace any that fails a criterion and say why. Record for each: advisory link, the exact field relationship violated, PoC source + license, vulnerable version + fix commit.

**Task 4.2 — pinned ASan builds** (`cve/vendor/fetch.sh`, `cve/vendor/README.md`). Fetch each project's vulnerable version by pinned tarball + sha256, build with `-fsanitize=address` into `cve/vendor/build/<project>/` (gitignored). `fetch.sh --verify` checks the sha256s.

**Task 4.3 — PoCs and original-parser drivers.** Per CVE: commit `cve/<id>/poc/<file>` + `PROVENANCE.md`; where redistribution is unclear, commit a generator script and the sha256 of its output instead. Write `cve/<id>/harness/original_driver.cpp` (an `LLVMFuzzerTestOneInput` reaching the vulnerable parse code; reuse the project's own fuzz driver when present). **Verify:** running the driver on the PoC under ASan reports the overflow. If a CVE cannot be reproduced this way, record it in `SELECTION.md` as "original not reproduced: <reason>" — the Wave 2 contract test still stands on its own.

**Done:** `SELECTION.md` complete with evidence; `fetch.sh` builds all three projects under ASan; each reproducible PoC reports an AddressSanitizer error on its original driver. `docs/reports/P4-report.md` records which originals reproduced and which did not, with reasons.

**Provenance rule (spec §11):** only inputs from public advisories or a documented generator; provenance in every `PROVENANCE.md`.
