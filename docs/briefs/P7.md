# Brief P7 — the six CVE contracts

**Worktrees:** one agent per family — `p7-tls`, `p7-png`, `p7-tiff` (branches of the same names). **Starts after P1 is merged and P4 has produced `cve/SELECTION.md` and the PoCs.**
**Read first:** spec §8.2, Task 7.1 in the plan, `cve/SELECTION.md` (from P4), Appendix A.

**Goal.** For each of your family's two CVEs, write the contract that rejects the triggering input — the heart of the proof. The claim is that a five-line contract catches a famous memory-safety bug.

**Consumes (from P1, frozen):** all schema combinators, `parse<S>`, `Parsed<S>`, the error kinds and paths. From P4: `cve/<id>/poc/` and the kind+path named in `SELECTION.md`.

**Per CVE (`cve/<id>/`), TDD:**
1. Write `reject.test.cpp` first: `parse<Contract>(Untrusted(poc))` fails with the exact `ErrorKind` and `path` named in `SELECTION.md` (e.g. CVE-2014-0160 → `Truncated`, `"payload"`); plus `accepts_well_formed_record` with a hand-built valid input.
2. Run → fails (no contract).
3. Write `contract.hpp` — only the structures involved in the bug, with a `Refine` (named after the rule) for any invariant the combinators do not express (CRC, cross-field relation).
4. Run → passes.
5. Write `README.md`: the bug in two paragraphs, the exact field relationship violated, how the contract expresses it, links.
6. Commit `cve/<id>: contract and reject test`.

**Done:** both of your family's CVEs rejected with the correct kind and path; valid inputs accepted; `docs/reports/P7-<family>-report.md`. Reject tests must build into the main `portcullis_tests` (they are ordinary `*.test.cpp` under `cve/<id>/`, added to the test glob via `tests/CMakeLists.txt` or a dedicated `cve` test target — follow whatever P1 left in place; if unclear, put the reject test under `tests/` including the contract header).

**Do not** touch library headers or another family's directory.
